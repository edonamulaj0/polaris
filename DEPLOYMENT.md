# Polaris — Cloudflare Pages Deployment Guide

Polaris is a **static Vite SPA** deployed to Cloudflare Pages. There is no server-side runtime in the Pages build itself — all API keys must stay **off the client bundle**.

---

## Build settings (Cloudflare Pages dashboard)

| Setting | Value |
|---|---|
| Build command | `npm run build` |
| Build output directory | `dist` |
| Node version | `22` (see `.node-version`) |
| Package manager | npm 10.x — run `npm run lockfile:pages` locally if `npm ci` fails on Pages |

---

## Environment variables

**Cloudflare Pages → Settings → Environment variables**

| Variable | Required on Pages? | Notes |
|---|---|---|
| `VITE_GOOGLE_CLIENT_ID` | Yes (for auth) | OAuth 2.0 Web client ID. Safe to expose — it is a public client identifier. |
| `ANTHROPIC_API_KEY` | **No** | Must **never** be set as a Pages env var with `VITE_` prefix or injected into the static build. LLM calls belong in a Worker or the batch script. |
| `VITE_ANTHROPIC_API_KEY` | **No — remove** | Deprecated. Was bundled into client JS (security risk). |
| `VITE_NEWS_API_KEY` | Optional | Only used by the Vite **dev proxy**; not available in production static builds. |
| `VITE_TWITTER_BEARER_TOKEN` | Optional | Dev proxy only. |

> **By design:** production Pages deploys need **zero secret API keys** in the dashboard. Curated content comes from committed `public/discussions.json`.

## Pre-deploy checklist

```bash
# 1. Build + automatic secret scan (postbuild hook)
npm run build

# 2. Manual grep (should print PASS)
npm run verify:bundle

# 3. Optional bundle analysis
npm run analyze
# Target: total JS < 400 KB gzipped
```

The `postbuild` script runs `verify:bundle`, which exits non-zero if `dist/` contains patterns like `sk-ant`, `ANTHROPIC_API_KEY`, or `VITE_ANTHROPIC`.

## Curated feed — nightly batch

Production feeds should use **`public/discussions.json`**, generated by the Node batch script (not the browser):

```bash
ANTHROPIC_API_KEY=sk-ant-... npm run fetch-discussions
```

Validate without writing to disk:

```bash
ANTHROPIC_API_KEY=sk-ant-... npm run fetch-discussions -- --dry-run | jq '.[0].title'
```

The script caps output at **20 posts** (`MAX_POSTS`).

### GitHub Actions (recommended)

Create `.github/workflows/fetch-discussions.yml`:

```yaml
name: Fetch discussions

on:
  schedule:
    - cron: '0 6 * * *'   # 06:00 UTC daily
  workflow_dispatch:

jobs:
  fetch:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: npm
      - run: npm ci
      - run: npm run fetch-discussions
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
      - uses: stefanzweifel/git-auto-commit-action@v5
        with:
          commit_message: 'chore: refresh discussions.json'
          file_pattern: public/discussions.json
```

Add `ANTHROPIC_API_KEY` to **GitHub → Settings → Secrets and variables → Actions**.

When `discussions.json` is committed, the next Pages deploy serves the curated feed with no client-side LLM or live Reddit calls.

## Cloudflare Worker — production LLM proxy (optional)

For live in-browser enrichment (dev-only today), add an edge proxy so the Anthropic key never reaches the bundle.

### 1. Create `workers/analyze/wrangler.toml`

```toml
name = "polaris-analyze"
main = "src/index.ts"
compatibility_date = "2024-11-01"

[vars]
# No secrets here — use wrangler secret put ANTHROPIC_API_KEY

[[routes]]
pattern = "yourdomain.com/api/analyze"
zone_name = "yourdomain.com"
```

### 2. Worker handler (`workers/analyze/src/index.ts`)

```ts
export default {
  async fetch(request: Request, env: { ANTHROPIC_API_KEY: string }): Promise<Response> {
    if (request.method !== 'POST') {
      return new Response('Method not allowed', { status: 405 })
    }
    const res = await fetch('https://api.anthropic.com/v1/messages', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'x-api-key': env.ANTHROPIC_API_KEY,
        'anthropic-version': '2023-06-01',
      },
      body: request.body,
    })
    return new Response(res.body, {
      status: res.status,
      headers: { 'Content-Type': 'application/json' },
    })
  },
}
```

### 3. Deploy

```bash
cd workers/analyze
npx wrangler secret put ANTHROPIC_API_KEY
npx wrangler deploy
```

### 4. Wire the client (future phase)

Update `src/services/anthropic.js` to call `/api/analyze` in production instead of falling back to `localAnalysis`.

## Local development

| Secret | Where | Purpose |
|---|---|---|
| `ANTHROPIC_API_KEY` | `.env` (no `VITE_` prefix) | Vite dev proxy at `/anthropic` + batch script |
| `VITE_GOOGLE_CLIENT_ID` | `.env` | Google Sign-In |

```bash
cp .env.example .env   # if present
npm run dev
```

The dev proxy for Anthropic is **disabled in production/preview builds** (`vite.config.js` guards on `mode === 'development'`).

---

## Manager PIN

The editor PIN is hashed (SHA-256) in `localStorage` on the client. It is **not** a server-side secret — treat it as a lightweight UI gate only.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `npm ci` fails on Pages with `@emnapi` errors | Run `npm run lockfile:pages` locally and commit `package-lock.json` |
| Feed shows mock data only | Run `fetch-discussions`, commit `public/discussions.json`, redeploy |
| Build fails with "SECRETS IN BUNDLE" | Remove any `VITE_*` API keys from env; grep `src/` for hardcoded keys |
| Google Sign-In blank | Set `VITE_GOOGLE_CLIENT_ID`; add Pages URL to authorized JS origins |
